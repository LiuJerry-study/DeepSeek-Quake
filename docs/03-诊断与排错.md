## 自检与诊断

托盘右键 →「**自检与诊断…**」，一眼看到卡在哪一环：

```
──── 1. 浏览器外壳 ────     找到哪些浏览器、当前用哪个、上次启动失败的原因
──── 2. 目标窗口 ────       有没有锁定窗口、可见性、是否已排除任务栏
──── 3. 热键 ────           配置值 / 实际生效值 / 组合键注册成功没 / 键盘钩子装上没
──── 4. 右键粘贴 ────       钩子装没装、右键按了几次、真正注入 Ctrl+V 几次
──── 5. 内部状态 ────       实时状态串
──── 6. 事件日志 ────       最近 60 条内部事件
```

- **「测试启动浏览器」**：手动跑一遍启动流程，直接告诉你成功还是失败、失败在哪一步；
- **「复制全部」**：整份报告复制到剪贴板，贴给谁都行；
- 命令行一键验证（小工具运行时）：`pwsh -File tests\verify-quake.ps1`。

小工具**不写日志文件**（原因见 [开发与编译](02-开发与编译.md)），所以诊断信息都在这个窗口里。


---

**双击 Ctrl 收不回去 / 别的页面也点不动？（2026-10-07 二次修复）**

**真正的根因**：收起和呼出原先都只用 `ShowWindowAsync`。它只是往目标窗口的消息队列
**投一条请求**就立刻返回——队列主人不处理时，它会**返回成功却什么都不做**。
于是「收起」报成功、窗口却还在屏幕上，你再按一次热键，工具看到"窗口已经不可见"
就执行"呼出"，结果什么也没变——这就是「怎么按都收不回去」。

实测证据：`win32probe\out\p1_matrix.txt` CASE 4 —— 对不泵消息的窗口调
`ShowWindowAsync(SW_HIDE)`，0~2ms 返回 `True`，而 `IsWindowVisible` 始终是 `True`。

**修法**：两个方向都改成两阶段——先异步短重试（便宜、绝不阻塞），确认目标线程
在泵消息之后再用同步 `ShowWindow` 兜底（一定生效）。同步调用会先探测
`SendMessageTimeout(WM_NULL, SMTO_ABORTIFHUNG)`，只有确认安全才用，避免在
不泵消息的窗口上永久阻塞。

验证：`repro\probe-hide-real.exe` 用反射驱动真实 exe 的 `Hide()`/`Show()`，
连续 5 轮收起/呼出全部成功（`PASS=8 FAIL=0`）。

另外两处相关问题：
- 右键抬起被吞掉会留下鼠标捕获，而**持有捕获的窗口即使被隐藏，仍会把点击抢走**
  （实测 `win32probe\out\p5_rbutton.txt`）——所以收起时会顺手清掉，日志写
  「已清掉残留的鼠标捕获」；
- 键盘钩子被系统静默摘掉后能自愈（见下面表格的 `hkl=`）。

| 看哪里 | 含义 | 怎么办 |
|---|---|---|
| 第 3 节「因『键按了但钩子没报』重装次数」> 0 | 键盘钩子被 Windows 静默摘掉过，工具已自动装回来 | 不用管，说明自愈生效了；次数一直在涨才需要反馈 |
| 第 5 节 `hkl=` | 同上（自愈次数） | 同上 |
| 第 5 节 `hfail=` | 累计「收起没能确认生效」次数 | 少数几次正常（浏览器忙）；一直在涨说明浏览器本身卡住了 |
| 第 5 节 `hid=[...]` | **收起时的现场快照**：`vis=`可见性 / `style=`WS_VISIBLE样式位 / `hung=`浏览器无响应 / `pump=`浏览器在不在处理消息 / `tries=`这次试了几次才成功 / `pend=`有没有待复核 | `pump=0` 说明浏览器自己卡住了（不是本工具的错）；`tries` 明显大于 1 说明异步指令不够用、已经靠同步兜底救回来了 |
| 第 5 节 `realhid=` | 交叉核对后的「真的隐藏了没有」 | 应该是 1（收起后）/ 0（呼出后） |
| 第 5 节 `showfail=` | 累计「呼出没能确认生效」次数 | 同上，一直涨要反馈 |
| 第 5 节 `slow=` | UI 消息循环卡顿（>1.5 秒）次数 | 应该是 0；不是 0 请反馈，说明还有地方在阻塞 |
| 事件日志里「收起未确认：浏览器没有响应窗口命令」 | **不是本工具的错**：浏览器 UI 线程此时不在处理窗口消息（卡住/模态），异步隐藏指令投不进去 | 再按一次热键；或等浏览器缓过来 |
| 事件日志里「显示后窗口仍不可见」 | 呼出这一步也没能确认生效 | 把 `hid=[...]` 一起贴给我 |

一个反直觉但很重要的细节：**隐藏一个已经持有鼠标捕获的窗口，并不会释放它的捕获**。
它照样会把之后所有点击抢走，你会觉得「整个桌面点不动」。这就是为什么「收起」里必须
显式清捕获，而不是指望窗口一藏就没事了。
